# Кандидатогенерация для поиска услуг Авито

Для каждого поискового запроса решение выбирает из корпуса в 189 тыс. объявлений 50 кандидатов для ранжирования. Метрика — Recall@50.

| | Recall@50 |
|---|---|
| BM25 по заголовку и описанию (отправная точка) | 0.70 |
| «Честная» валидация (только объявления бенчмарка, 3 699 запросов) | 0.927 |
| Бенчмарк без векторного канала | 0.884 |
| **Бенчмарк** (полный трейн, K=4000, эмбеддинги e5-large, ансамбль из 3 моделей) | **0.902** |

Подробный разбор задачи, экспериментов и ограничений — в [REPORT.md](REPORT.md).

## Как это работает

```
запрос ──► географический пул ──► 6 каналов поиска ──► ~4000 кандидатов ──► LightGBM LambdaRank ──► топ-50
           (своя локация +        (BM25, расширение      (объединение)        (51 признак,
            переходы из трейна +   по похожим запросам,                        ансамбль из 3 моделей)
            радиус 30 км)          символьные n-граммы,
                                   популярность, векторы)
```

1. **Пул по географии.** 83% выбранных объявлений находятся в той же локации, что и поиск. Поиск по региону или стране ведёт в конкретные города, поэтому переходы «локация поиска → локация объявления» берутся из трейна.
2. **Каналы поиска внутри пула.** Используются BM25 по заголовку, параметрам и описанию (все слова лемматизированы) и расширение запроса словами из объявлений, которые выбирали по похожим запросам в трейне. Кроме того, есть символьные n-граммы (опечатки, словоформы) и «популярные» объявления, в которых есть все слова запроса. Последний канал — векторный: ближайшие по косинусу эмбеддингов.
3. **Ранкер.** LightGBM LambdaRank ранжирует кандидатов по признакам текста, географии, подкатегории и сигналов от похожих запросов. Итог — ансамбль из трёх моделей, обученных на непересекающихся частях трейна.

## Быстрый старт

```bash
pip install -r requirements.txt
# положите benchmark_items.parquet, benchmark_queries.parquet, train.parquet в data/
python -m scripts.prepare_data   # ~2 мин
python -m scripts.predict        # ~20 мин, модели уже лежат в models/ → answer.csv
```

Полный пайплайн с обучением: `./run_all.sh` (около 2.5 часов: 4 CPU + одна A5000).

## Настройка

Все параметры находятся в `candgen/config.py`. Пути можно задать переменными окружения `CANDGEN_DATA_DIR` и `CANDGEN_WORK_DIR`.
Главные параметры:

- `K_TRAIN = 800` — сколько кандидатов на запрос генерируется при обучении (ограничено памятью).
- `K_PREDICT = 4000` — сколько кандидатов генерируется при предсказании. Чем больше, тем выше Recall@50: на валидации 800 → 2000 даёт +1.1 п., 2000 → 4000 — ещё +0.4 п.
- `GROUPS_PER_BAG`, `N_BAGS` — объём обучающей выборки и число моделей в ансамбле.

## Устройства

| Этап | Где считается | Как настроить |
|---|---|---|
| prepare_data, build_features, predict (кандидаты и признаки) | CPU, один поток (numpy/scipy) | — ; GPU не используется |
| train_ranker, evaluate, predict (LightGBM) | CPU, все ядра | `CANDGEN_THREADS=8`; GPU: `CANDGEN_LGB_DEVICE=cuda` (нужна сборка LightGBM с CUDA) |
| compute_embeddings | GPU (fp16) | `EMB_DEVICE=cuda:0` в `run_all.sh` или `--device` |

## Векторный поиск

Включён в `run_all.sh` (шаг 1b): после `prepare_data` считаются эмбеддинги объявлений и запросов моделью `intfloat/multilingual-e5-large` на GPU в fp16 (~20 мин на A5000). `ItemIndex` подхватывает `artifacts/embeddings/*`: в кандидаты добавляется канал «ближайшие по косинусу», а в признаки — `s_emb`, `rk_emb`, `emb_gap`.

```bash
EMB_MODEL=deepvk/USER-bge-m3 EMB_DEVICE=cuda:1 ./run_all.sh   # другая модель / видеокарта
```

Векторный канал дал +1.9 п.п. на бенчмарке (0.884 → 0.902) и +1.1 п.п. на honest-валидации. Нужен доступ к HuggingFace. Ранкеры, обученные без эмбеддингов, с ними не совместимы: после смены модели эмбеддингов пайплайн нужно прогнать целиком.

## Требования к ресурсам

Исследование велось на 2 CPU и 8 ГБ RAM. Отсюда ограничения в коде: признаки пишутся по фолдам в отдельные файлы, а обучение идёт на плотной float32-матрице примерно из 8 млн строк. Если памяти больше, можно поднять `GROUPS_PER_BAG` — рост числа обучающих запросов улучшал качество.

С векторным каналом требования выше: эмбеддинги корпуса (515 895 × 1024, float32) занимают 2.1 ГБ в каждом процессе, плюс до 264 МБ на блок скоров (`_EmbScores.CHUNK = 128`, при нехватке памяти уменьшите). Нужно около 16 ГБ RAM и видеокарта для шага 1b.
